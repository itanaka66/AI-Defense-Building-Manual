# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第55部です。第54部で、LLM の出力の伏せ字と承認の方針を入れました。ここでは次のことを行います。

1. 実際のアラートや AI の分析に進む前に、VM 230 の全体を統合して点検する
2. 外に通信しない試験（合成のイベント25件・Ollama の答えを模した分析9件）で、安全の境目を確かめる
3. API へのアクセスの制御と、大量の要求（DoS）への備えを点検する
4. Uvicorn の同時接続の上限・AI の分析の同時の実行の上限・HTTP の本文の大きさの上限を入れる

## 本書の表記

- コマンドやプログラムは、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 実行先は、各手順の「実行先」に示します。
  - **VM 230**：ai-defense-manager（root）

# 第1章　統合の点検

# 第3章　アクセスの制御と DoS の点検

## 3.1　アクセスの制御

> **実行先：VM 230**

⟦C4⟧

API は `127.0.0.1:8000` だけで待ち受け、実行のユーザーは `ai-defense`、`NoNewPrivileges=yes`・`ProtectSystem=strict` でしたが、アプリケーションの中の認証・認可・CORS のミドルウェアはありませんでした。

## 3.2　ドキュメントとルート

> **実行先：VM 230**

⟦C5⟧

| エンドポイント | 状態 |
|---|---|
| `/docs` | 有効 |
| `/redoc` | 有効 |
| `/openapi.json` | 有効 |
| `/health` | 有効 |
| API の認証の方式 | なし |

`127.0.0.1` だけですが、認証なしで API の仕様を見られる状態です。本番では `/docs`・`/redoc`・`/openapi.json` を無効にする方針にします。

## 3.3　大量の要求への備え

> **実行先：VM 230**

⟦C6⟧

⟦C7⟧

| 項目 | 状態 |
|---|---|
| イベントの数の上限 | 100件 |
| Wazuh から取る数の上限 | 100件 |
| LLM の応答の時間切れ | 60秒 |
| Relay との通信の時間切れ | 15秒 |
| SQLite のロックを待つ上限 | 5秒 |
| メモリの上限 | 1GiB |
| HTTP の本文の大きさの上限 | **無い** |
| 同時の接続の上限（`--limit-concurrency`） | **指定なし** |
| AI の分析の同時の実行の上限 | **無い** |

Worker が1つでも、非同期の API なので複数の要求を同時に処理します。2つの分析の API は Ollama に分析を頼むので、要求が集まると待ち時間や時間切れが増えます（Ollama の側は並列の数が1）。

## 3.4　入れる制限

| 対策 | 値 |
|---|---|
| Uvicorn の同時の接続 | 8 |
| 接続のバックログ | 32 |
| Keep-Alive の時間切れ | 5秒 |
| AI の分析の同時の実行 | 1（超えた分は待たせる） |
| HTTP の本文の大きさ | 256KiB（超えたら `HTTP 413`） |
| Worker の数 | 1のまま |

Uvicorn の接続の制限だけでは本文の大きさは制限できないので、本文を読みながら大きさを数える ASGI のミドルウェアを足します。SQLite への保存・Relay との通信・LLM へのプロンプト・安全の方針は変えません。

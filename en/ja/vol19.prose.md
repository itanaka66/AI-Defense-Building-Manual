# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」前編の第19部です。第18部までで、Wazuh のアラートを AI（Ollama の qwen3:8b）で分析し、結果を SQLite に残せるようになりました。ここでは、**SQLite に何が残るか**と、**LLM に何を渡しているか**を確かめ、余計な情報を渡さないように直します。

1. SQLite のカラムと保存の処理を確かめる
2. LLM に送るイベントの項目を、決めた6項目だけにする
3. イベントのカテゴリを、決めた固定の値に置き換える
4. LLM に送るイベントの要約から、秘密の情報・メールアドレス・IPアドレスを伏せ字にする

元の Wazuh のイベントと SQLite の保存の仕様は変えません。

## 本書の表記

- コマンドやプログラムは、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 実行先は **ai-defense-manager VM 230（root）** です。

# 第1章　保存と入力の点検

Wazuh の `full_log`、任意の `data`、ユーザー名、コマンド、パスワードを保存するカラムはありません。中身を確かめる必要があるのは、AI が作った `summary`・`reasoning` と、Wazuh から来た `event_summary` です。

## 1.2　保存・取得・データモデル・分析のコード

⟦C1⟧

SQL はすべてプレースホルダーを使っていて、SQL インジェクションの対策はできています。

⟦C2⟧

`full_log`、任意の `data`、コマンド、パスワードは参照していません。ただし、`rule.description`（要約の元）と `decoder.name`／`location`（カテゴリの元）は外から来た文字列なので、思わぬ情報がまじる可能性は残ります。

⟦C3⟧

⟦C4⟧

AI の分析のサービスには、次のよい点があります。

- イベントの説明やコンテキストを「信頼できないデータ」として扱うよう指示している
- JSON Schema で出力の形を決めている
- 証拠のイベントIDが入力に含まれるかを検証している
- 内部のIPの遮断を禁止し、遮断の提案には複数の証拠・グローバルIP・TTL 900秒まで・人の承認を求めている

一方、`request.model_dump(mode="json")` をそのまま LLM に渡しているため、分析に必要のない `agent_name`、`agent_id`、`rule_description`、IPアドレスなども送られています。

# 第3章　カテゴリと要約の中身を守る

## 3.1　どこに情報がまじるか

⟦C18⟧

- `description` → `event_summary`：最大512文字。そのまま LLM に送られる
- `decoder` か `location` → `event_category`：最大64文字。そのまま LLM に送られる。`location` はログの取り元なので、ファイルのパスやホストの情報が入ることがある

方針は次のとおりです。

1. `event_category` は、決めた固定のカテゴリに置き換える
2. `event_summary` は、API キー・トークン・パスワード・メールアドレス・IPアドレスなどを見つけて伏せ字にする
3. 伏せ字にした後も、長さの上限を守る
4. 元の Wazuh のイベントと SQLite の保存の処理は変えない

## 3.2　使えるライブラリ

⟦C19⟧

⟦C20⟧

依存関係は `requirements.lock` で管理しています。秘密の情報を見つける専用のライブラリはないので、Python の標準の `re` と `ipaddress` で作ります。

IPアドレスやメールアドレスを消してしまうと攻撃元の特定に必要な情報まで失うため、消さずに次の伏せ字に置き換えます。

| 情報 | 置き換え |
|---|---|
| API キー・Bearer トークン・パスワード | `[REDACTED_SECRET]` |
| メールアドレス | `[REDACTED_EMAIL]` |
| IPアドレス（内部・外部とも） | `[REDACTED_IP]` |
| 文字列でない入力など | `[REDACTED_EVENT]` |

# おわりに

第19部で、LLM に渡す情報を次のように絞りました。

| 対策 | 内容 |
|---|---|
| 送る項目 | 6項目と分析の言語だけ |
| カテゴリ | 固定の値（知らないものは `other`） |
| 要約 | 秘密の情報・メールアドレス・IPアドレスを伏せ字にしてから送る |

次の部では、AI の分析が失敗する問題を直し、SQLite に保存する要約にも伏せ字を使います。

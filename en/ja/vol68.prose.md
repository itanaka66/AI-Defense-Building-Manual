# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第68部です。第67部で、`local_rules.xml` を直した候補のファイルを `/tmp` に作りました。本番に置く前に、Wazuh 自身の検査（`wazuh-analysisd -t`）で、候補をルールとして受け入れるかを確かめます。

`wazuh-analysisd -t` は、ふつうは本番の設定のディレクトリを読みます。`wazuh-logtest` も本番のルールを読み込みます。そこで、`wazuh-analysisd` の `-D`（指定したディレクトリに `chroot` する）を使い、**`/tmp` に作った隔離した環境**で検査します。

- 標準のルール・デコーダー・リストと、候補の `local_rules.xml` だけを置く
- 本番の `ossec.conf` には認証の情報（TLS の証明書と秘密の鍵・CA・パスワードなど）が入るので、丸ごとは写さず、秘密を含まない最小の設定を作る
- 本番の Wazuh Manager は起動・再起動しない

## 本書の表記

- コマンドやプログラムは、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 実行先は、各手順の「実行先」に示します。
  - **VM 220**：security-core（root）

> **注意：** Wazuh の検査のコマンドは root でしか動きません（一般のユーザー `ag` では `Permission denied` や終了コード 126 になります）。`ag` でログインしているときは、次で root になってから実行します。

# 第3章　隔離した環境で検査する

## 3.1　XML の宣言を外す

隔離した設定の先頭に XML の宣言（`<?xml …?>`）があり、本番の設定には無いことがわかりました。隔離した設定だけから宣言を外して検査します。

> **実行先：VM 220**

⟦C10⟧

宣言を外すと、それまでの設定の読み込みのエラー（1226）は出なくなり、次は `internal_options.conf` の `Permission denied` になりました。

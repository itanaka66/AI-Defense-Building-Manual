# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」中編の第30部です。第28部・第29部で、Collector は試験用の隠しディレクトリ（`.acl-inheritance-test.bkv8vd`）に入れずに止まっていたことを突き止め、読み取り位置を直して動かし直しました。ただし、このディレクトリは残っているため、次にファイルが切り替わったときにまた止まるおそれがあります。

ここでは、ディレクトリを消したり Collector の権限を広げたりするのではなく、**前のファイルを探すときに、名前が `.` で始まるディレクトリ（隠しディレクトリ）を探さない**ように、Collector のコードを2行だけ直します。

- 本物のアラートの置き場（`2026/Nov` など）は、これまでどおり探す
- ふつうのディレクトリに入れないときのエラーは、これまでどおり止まる（握りつぶさない）
- シンボリックリンクをたどらない作りは変えない

最後に、ログの切り替え（ローテーション）のときの処理と、状態ファイル・重複の扱いをコードで確かめます。

# 第4章　ローテーションの処理の確認

> **実行先：VM 220**

⟦C28⟧

| 状況 | Collector の動き |
|---|---|
| ふつうの行 | PostgreSQL に保存してから位置を保存する |
| PostgreSQL につながらない・保存に失敗 | 行の頭に戻ってやり直す |
| ファイルの最後が途中の行 | 切り替わるのを待つ |
| 途中の行のまま切り替わった | その行を捨てて、新しい inode に切り替える |
| 最後まで読んで切り替わった | 新しい inode に切り替える |
| 位置の保存に失敗 | 新しいファイルに切り替えずにやり直す |

⟦C30⟧

⟦C31⟧

`event_id` は Wazuh のアラートの `alert["id"]` で、重複（SQLSTATE `23505`）だけを「すでにある」として扱います。INSERT を確定してから位置を進めるので、保存と位置の保存のあいだで止まって同じ行を読み直しても、二重には登録されません。

# おわりに

第30部で、Collector が隠しディレクトリで止まらないようにしました。

| 項目 | 結果 |
|---|---|
| 直したところ | `find_inode_file()` で、名前が `.` で始まるディレクトリを探さない（2行） |
| バックアップ | `collector.py.pre-hidden-dir-fix-20261121` |
| 試験 | Collector のユーザーで `TEST: PASS` |
| 反映 | 再起動して `NRestarts=0`、PostgreSQL への保存も確認 |
| 隠しディレクトリ | 消していない（残っていても Collector は止まらない） |

構築時は、このあと Wazuh のログの切り替えが `copytruncate` かどうかなど、ローテーションの方式の確認に進みましたが、その結果は受け取った記録の範囲にはありません（不足情報メモ 30-B）。

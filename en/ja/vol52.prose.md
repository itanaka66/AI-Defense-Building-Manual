# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第52部です。第51部で、VM 230 から VM 220 の Relay への TLS と認証を確かめました。ここでは、実際の Wazuh のアラートを取ります。

1. VM 230 の `GET /api/v1/wazuh/events` で、最大10件・直近15分のアラートを1回だけ取る
2. Relay が `HTTP 502` を返したので、原因を、アラートの値を表示せずに調べる
3. 原因（`relay.py` に `import re` が無い）を1行で直し、Relay を再起動する
4. もう一度アラートを取り、7項目の許可リストのとおりに受け取れることを確かめる

アラートの本文・IP アドレス・説明・ユーザー名、パスワードやトークンは表示しません。AI の分析・SQLite への保存・Ollama への送信もしません。

## 本書の表記

- コマンドやプログラムは、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 実行先は、各手順の「実行先」に示します。
  - **VM 230**：ai-defense-manager（root）
  - **VM 220**：security-core（root）

# 第2章　502 の原因を調べる

## 2.1　Indexer と Relay の状態

Indexer への HTTP のリクエストはせず、状態とログだけを見ます。

> **実行先：VM 220**

⟦C2⟧

Wazuh Indexer は `active (running)` で、`127.0.0.1:9200` で待ち受け、直近30分のエラーはありませんでした。Relay のログには `/v1/alerts` に対する `HTTP 502` が記録されていました。Relay は例外をすべて `indexer_unavailable` に変えるので、ログだけでは原因はわかりません。

## 2.2　Indexer の検索の権限

Relay と同じユーザー（`ai-defense-reader`）で、アラートの本文を返さない検索（`size: 0`）を試します。

> **実行先：VM 220**

⟦C3⟧

| 確かめたこと | 結果 |
|---|---|
| 管理者の証明書による検索 | `HTTP 200` |
| `ai-defense-reader` による検索 | `HTTP 200` |
| シャード | 21/21 成功 |
| タイムアウト | なし |

`ai-defense-reader` はアラートのインデックスを検索できます。ロールに権限を足す必要はありません。

> **参考：** Indexer のルートの URL（`/`）に `ai-defense-reader` でアクセスすると `403`（`cluster:monitor/main` の権限が無い）になりますが、アラートの検索とは別の話です。最小の権限のまま、クラスタの権限は空にしておきます。

## 2.3　Relay と同じ条件で検索する

Relay の検索は、`timestamp` の15分の範囲、新しい順、7項目だけの `_source` です。同じ条件で、文書を返さずに試します。

> **実行先：VM 220**

⟦C4⟧

TLS の検証・認証・インデックスへのアクセス・範囲の指定・並べ方・項目の指定・応答の JSON の形は、すべて正常でした。**原因は、検索の結果が1件以上返ったときの処理**に絞られます。

## 2.4　実際のアラートで、値を見ずに確かめる

実際のアラートを最大10件取り、VM 220 の中のメモリだけで、件数・型・伏せ字の処理の結果・例外のクラスの名前だけを数えます。

> **実行先：VM 220**

⟦C5⟧

| 確かめたこと | 結果 |
|---|---|
| Indexer の検索 | `HTTP 200` |
| 取れたアラート | 1件 |
| 7項目の型 | すべて考えたとおり |
| 伏せ字の処理（`sanitize_alert()`） | **`NameError`** |

## 2.5　読み込んでいるモジュール

> **実行先：VM 220**

⟦C6⟧

**`relay.py` に `import re` がありませんでした。** `sanitize_alert()` は `rule.groups`・`rule.id`・`agent.id` を確かめるのに `re.fullmatch()` を使っています（第49部で足した処理）。そのため、実際のアラートを処理すると `NameError` になり、Relay が `502` を返していました。

# おわりに

第52部で、VM 230 から実際の Wazuh のアラートを、許可した項目だけで受け取れるようになりました。

| 項目 | 結果 |
|---|---|
| 502 の原因 | `relay.py` に `import re` が無く、`sanitize_alert()` が `NameError` になっていた |
| 対策 | `import re` を1行足し、控えを作ってから構文と伏せ字の処理を試し、Relay を再起動した |
| Indexer の権限 | 変えていない（`ai-defense-reader` は検索できる。クラスタの権限は空のまま） |
| アラートの取得 | `HTTP 200`、1件、許可リストの検査に合格 |

経路は、Wazuh Indexer（VM 220 `127.0.0.1:9200`）→ Relay（VM 220 `:8765`、7項目に絞る）→ AI Defense Manager（VM 230 `:8000`）です。次の第53部では、VM 230 の中で、受け取ったアラートが分析・保存・防御の提案へどうつながるかを点検します。

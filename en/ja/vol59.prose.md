# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第59部です。第57部・第58部で作って試した API のトークンによる認証を、本番に入れます。

1. 本番の SQLite に、トークンを管理するテーブルを作る
2. クライアント用のトークンを1つ発行し、ファイルと DB が合っていることを確かめる
3. サービスを再起動して、認証を有効にする
4. 本番で、認証の順番・Wazuh の取得の API の認証・ログに漏れないこと・最後に使った時刻の更新を確かめる

本番の試験では、AI の分析・履歴の保存・Wazuh や Ollama への通信が起きないように、入力の検証で必ず止まる要求を使います。

> **注意：** トークンの中身は、画面に出したり、貼り付けたり、ほかの人に渡したりしないでください。

# 第4章　本番で認証を確かめる

## 4.1　分析の API の入力の形

> **実行先：VM 230**

⟦C7⟧

⟦C8⟧

分析の API は、認証のあとに `analyze_events()` を呼び、そのあと履歴を保存します。`events` は1件以上が必須なので、JSON としては正しく、`events` が空の `{"events":[]}` を送れば、入力の検証で必ず止まり、分析には進みません。

> **参考：** 正しくない JSON（`{` だけなど）を送ると、FastAPI が本文の解析のエラー（`422`）を認証より先に返すことがあり、認証の試験になりません。

## 4.2　認証の順番

> **実行先：VM 230**

⟦C9⟧

| 試験 | HTTP | 判定 |
|---|---:|---|
| トークンなし | 401 | 合格 |
| 正しいトークン＋正しくない入力 | 422 | 合格（認証を通ったあと、入力の検証で拒まれた） |
| `/health` | 200 | 合格 |

## 4.3　Wazuh の取得の API

本番の Wazuh へつながないように、認証の情報なし・正しくないトークンの要求だけを送ります。

> **実行先：VM 230**

⟦C10⟧

| 試験 | HTTP | 判定 |
|---|---:|---|
| トークンなし | 401 | 合格 |
| 正しくない Bearer のトークン | 401 | 合格 |
| `/health` | 200 | 合格 |

Wazuh への通信は起きていません。`403`（権限の不足）は第57部の独立した試験の結果を使い、本番の DB に試験用のトークンは足しません。

## 4.4　情報が漏れないか

> **実行先：VM 230**

⟦C11⟧

| 項目 | 判定 |
|---|---|
| Bearer のトークンをログに出さない | 合格（認証の処理に logger・print が無い） |
| SHA-256 の比較 | 合格（`hmac.compare_digest()`） |
| 期限切れ・失効の判定 | 合格 |
| スコープ不足 | 合格（`403`） |
| `last_used_at` | 合格（認証が成功したときだけ更新） |
| API の例外の応答 | 合格（決まったメッセージを返す） |

> **実行先：VM 230**

⟦C12⟧

正しくないトークンで `401` になり、journal には接続元・パス・ステータスだけが記録され、トークンの値は出ていませんでした。

## 4.5　最後に使った時刻

本番のトークンを画面や引数に出さずに、認証のついた POST を1回だけ送ります。`events: []` で `422` になるので、分析・履歴の保存・Wazuh への接続は起きません。

> **実行先：VM 230**

⟦C13⟧

認証が成功したときに、本番の SQLite の `last_used_at` が更新されたことを確かめました。

# おわりに

第59部で、API のトークンによる認証を本番に入れました。

| 項目 | 結果 |
|---|---|
| 本番の DB | `api_tokens` と期限のインデックスを作った |
| トークン | `ai-defense-client`（`read,analyze`、30日）を発行。`/root/ai-defense-client.token`（`600`） |
| サービス | 再起動し、認証が有効（`/health` は認証なし） |
| 本番の試験 | トークンなし・正しくないトークンは `401`、正しいトークンは認証を通る、ログにトークンは出ない、`last_used_at` が更新される |
| ドキュメント | `/docs`・`/redoc`・`/openapi.json` は無効 |

> **運用の注意：** トークンの有効期限は30日です。期限の前に `aidm-api-token` で新しいトークンを発行し、古いものを `revoke` で失効させます（運用マニュアル）。

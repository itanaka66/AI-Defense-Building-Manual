# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」前編の第5部です。第4部でテスト用のコピーに加えた強化を仕上げ、本番のCollectorに反映して、実際の運用で正しく動くことを確認します。

## 本書の表記

- コマンドやファイル内容は、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 各手順の冒頭に「実行先」を示します。
- 「実行結果（例）」は構築時の実際の出力です。お使いの環境では、inode・サイズ・日時・ハッシュなどが異なります。
- 認証情報や状態ファイルの中身は表示しません。

# 第5部のまとめ

第5部で、強化版のCollectorが本番で動き始めました。

| 項目 | 状態 |
|---|---|
| 本番のCollector | `/usr/local/lib/wazuh-collector/collector.py`（強化版、18,898バイト） |
| サービス | `wazuh-collector.service`（active、自動起動） |
| 起動時の処理 | 現在のファイルを優先して再開し、旧ファイルを確認できない場合は起動を拒否（fail-closed） |
| 照合結果 | 同じ期間のWazuhのアラートとDBの件数が一致（230件） |

第4部・第5部を通じて、Collectorに加えた強化は次のとおりです。

| 領域 | 内容 |
|---|---|
| 入力 | 型・範囲・長さの検証、制御文字（C0・DEL・C1・Unicodeの書式制御文字）の除去、日時の長さの上限 |
| 行サイズ | 1行1 MiBの上限、64 KiB単位の読み飛ばし |
| ローテーション | 未完了の行・EOF・読み飛ばし中の切り替え、実際に開いたファイルのinode、`stat`・`open`・`fstat` の失敗時の再試行 |
| 状態ファイル | 値の厳格な検証、DB登録の成功後にだけ保存 |
| DB | 接続失敗時の巻き戻しと再接続、一意制約による重複の拒否（SELECT権限は不要） |
| 起動と終了 | 最小権限のままの起動、fail-closed、ファイルとDB接続の独立したクローズ |

> **運用上の注意：** 9.2のとおり、日付ごとのアーカイブは `alerts/年/月` に移るため、Collectorが止まっている間に日付が変わると、起動時に旧ファイルを確認できず、起動を拒否します。長時間止めたあとに起動できない場合は、状態ファイルと `alerts` 以下を確認してから対処してください。

次の段階では、DBに蓄積したアラートの重複防止とデータの整合性をさらに確かめ（STEP 325以降）、監視の仕組みを広げていきます。

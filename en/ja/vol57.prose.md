# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第57部です。第56部で決めた設計にそって、AI Defense Manager の API にトークンによる認証を作り、本番の DB を使わない独立した環境で試します。

| 対象 | 内容 |
|---|---|
| 保存 | 既存の `ai-defense.db` に、認証専用のテーブル `api_tokens` を足す。トークンの SHA-256 のハッシュだけを保存し、平文は保存しない |
| トークン | 256ビット相当の暗号の乱数で作る |
| 発行 | root 専用の CLI（`/usr/local/sbin/aidm-api-token`）で発行・失効・一覧。平文のトークンは root 専用のファイル（`600`）に一度だけ書き出し、画面やログには出さない |
| 権限（スコープ） | `read`（Wazuh のイベントの取得）・`analyze`（分析） |
| 認証しないもの | `/health` |
| 無効にするもの | `/docs`・`/redoc`・`/openapi.json` |
| サービス | `ai-defense` のまま、DB からハッシュを読む |

既存の分析の履歴・証拠・承認・監査のログのテーブルとデータ、Relay の認証の情報は変えません。この部では、サービスの再起動・本番のトークンの発行・Wazuh の取得・Ollama の推論はしません。

# 第3章　独立した環境で試す

## 3.1　認証の処理の試験

テスト用の DB は一時ディレクトリに作り、終わったら消します。本番の DB・Wazuh・Ollama にはつながりません。

> **実行先：VM 230**

⟦C5⟧

トークンの発行・ハッシュでの保存・正しくない／期限切れ／失効したトークンを拒む・スコープが足りないときに拒む、はすべて合格でした。

3つのルートのスコープの検査は `FAIL` と出ましたが、これは試験のコードの問題でした（3.2）。

## 3.2　ルートの登録を確かめる

> **実行先：VM 230**

⟦C6⟧

ソースでは、3つのルートすべてに `Depends(require_scope(...))` が書かれていました。

> **実行先：VM 230**

⟦C7⟧

FastAPI 0.165.0 では、`include_router()` で登録したルーターは `_IncludedRouter` として後で展開されます。試験のコードが `app.routes` を直接たどったため、3つの API のルートを見つけられなかったのでした。展開したルートで確かめ直します。

> **実行先：VM 230**

⟦C8⟧

| API | 必要なスコープ | 結果 |
|---|---|---|
| `GET /api/v1/wazuh/events` | `read` | 合格 |
| `POST /api/v1/analysis` | `analyze` | 合格 |
| `POST /api/v1/wazuh/analyze` | `analyze` | 合格 |
| `GET /health` | 要らない | 合格 |

## 3.3　HTTP での認証の試験

> **実行先：VM 230**

⟦C9⟧

トークンなしで `401`、`read` のトークンで分析の API を拒む `403`、`/health` は認証なし、は合格でした。残りは試験の期待の値の問題で、次のように確かめました。

> **実行先：VM 230**

⟦C10⟧

- `analyze` のトークンで `GET /events` は `403`（トークンは正しいが `read` が無い）。仕様どおり
- `POST /analysis` は `422`（認証を通り、本文の必須の `events` が無い）
- `POST /wazuh/analyze` は `502`。空の本文 `{}` でも `limit=50`・`since_minutes=60` が自動で入り、認証のあとに実際の取得・分析に進んだため

> **実行先：VM 230**

⟦C11⟧

そこで、Wazuh の取得と Ollama を完全に模した試験に切り替えます。

## 3.4　Wazuh の API の試験

`fetch_wazuh_events` を空の配列を返す関数に差し替え、AI の分析・履歴の保存・外への通信に進ませません。

> **実行先：VM 230**

⟦C12⟧

GET は `read` のトークンで `200`、`analyze` のトークンで `403`、POST はトークンなしで `401` でした。POST の本文を省いた試験は `422` になりました（既定の値があっても、本文そのものは必須）。本文を付けて試し直します。

> **実行先：VM 230**

⟦C13⟧

| 試験 | 結果 |
|---|---:|
| `read` のトークンで GET | 200 |
| `analyze` のトークンで GET | 403 |
| `analyze` のトークンで POST | 404（模した空のイベントの応答） |
| `read` のトークンで POST | 403 |
| トークンなしで POST | 401 |
| 模した取得の関数が呼ばれた回数 | 1回 |

認証で拒まれた要求では、Wazuh の取得の関数は呼ばれていません。

## 3.5　分析の API の試験

`source="internal"` のテスト用のイベントを使い、分析の結果は決まった `no_action` の提案を返す模したものにし、履歴の保存も模します。

> **実行先：VM 230**

⟦C14⟧

| 試験 | 結果 |
|---|---:|
| `analyze` のトークン | 200 |
| `read` のトークン | 403 |
| トークンなし | 401 |
| 分析・履歴の保存（模したもの） | 認証が通ったときだけ1回 |

# おわりに

第57部で、API のトークンによる認証を作り、独立した環境で確かめました。

| 項目 | 結果 |
|---|---|
| 認証 | Bearer のトークン、スコープ `read`・`analyze`、SHA-256 のハッシュで保存、`hmac.compare_digest` で照合 |
| CLI | `/usr/local/sbin/aidm-api-token`（root 専用）で発行・失効・一覧 |
| ドキュメント | `/docs`・`/redoc`・`/openapi.json` を無効にした |
| 試験 | 3つの API すべてで、トークンなし `401`・権限不足 `403`・正しいスコープで通る |
| 本番 | まだ反映していない（認証のテーブルなし、サービスは再起動していない） |

次の第58部では、CLI とトークンの処理を細かく点検して強くし、本番に入れる前の最後の点検をします。

# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第54部です。第53部の点検で、LLM の出力（`summary`・`reasoning`）が伏せ字にされずに保存・返却されること、承認が要るかどうかを LLM が決められることがわかりました。ここでは次のように直します。

| 対象 | 直し方 |
|---|---|
| イベントの入力 | いまの伏せ字の処理（512文字）のまま |
| LLM の `summary`・`reasoning` | 専用の入口で秘密の情報・個人の情報を除き、2,000文字・4,000文字に制限する |
| API の返す値・SQLite への保存 | 伏せ字にした提案だけ |
| 承認が要るかどうか | サーバーの側で決める。`no_action` のほかはすべて人の承認が要る |
| 一時的な IP の遮断 | 必ず人の承認が要り、TTL は最大900秒 |
| Wazuh のイベントの取得の API | 返す要約・説明も伏せ字にする |

LLM は分析の担当に限り、出力の安全と承認の判断は AI Defense Manager の側で保証します。Action Gateway（実際の操作の実行）は、まだ作りません。

## 本書の表記

# 第2章　LLM の出力の伏せ字と承認の方針を入れる

## 2.1　4つのファイルを書き換える

イベント用の伏せ字の処理の512文字の制限は残したまま、LLM の出力用に 2,000文字・4,000文字の専用の入口を足します。承認が要るかどうかは LLM の値を信じず、`no_action` のほかはサーバーの側で必ず承認が要るようにし、DB に保存するときにも同じ規則をもう一度あてます。

> **実行先：VM 230**

⟦C1⟧

4つのファイルの書き込みと Python の構文の検査は成功し、所有者・権限もそのままでした。

## 2.2　機能の試験（10件）

実際の DB にはつながず、試験用の偽の DB で確かめます。

> **実行先：VM 230**

⟦C2⟧

**10件すべて合格**でした。

- イベントの要約の512文字の制限は変わっていない
- LLM の `summary`・`reasoning` は 2,000文字・4,000文字に制限され、秘密の情報が伏せ字になる
- `no_action` のほかは、LLM が `requires_human_approval=false` を返しても、サーバーの側で承認が要るようにする
- SQLite への保存でも、同じ承認の規則と伏せ字があたる

## 2.3　承認の方針の境目（5件）

> **実行先：VM 230**

⟦C3⟧

| 確かめたこと | 結果 |
|---|---|
| `no_action` は承認が要らない | 合格 |
| 公開の IP の一時的な遮断は承認を待つ | 合格 |
| 承認なしの遮断の提案を拒む | 合格 |
| プライベートの IP の遮断の提案を拒む | 合格 |
| 証拠のイベントが1件だけの遮断の提案を拒む | 合格 |

ここまでの機能の試験は15件すべて合格です。

# 第3章　Wazuh のイベントの取得の API も伏せ字にする

## 3.1　API の返す値の点検

> **実行先：VM 230**

⟦C4⟧

2つの分析の API は、`analyze_events()` が返した提案を保存してから返すので、第2章の伏せ字と承認の方針が応答にもあたります。ただし、`GET /api/v1/wazuh/events` は AI の分析を通らず、`fetch_wazuh_events()` の結果をそのまま返します。

## 3.2　取得の API の変換

> **実行先：VM 230**

⟦C5⟧

`_convert_alert()` は、Wazuh の `rule.description` を、そのまま `event_summary` と `rule_description` に入れていました。そのため `GET /api/v1/wazuh/events` では、伏せ字にされていない文字列が返ることがあります。

## 3.3　直す

`wazuh_relay.py` だけを、控えを作ってから直し、`event_summary` と `rule_description` の両方に `sanitize_event_summary()` をあてます。合成したデータで確かめます。

> **実行先：VM 230**

⟦C6⟧

直したあとの合成の試験は**9件すべて合格**で、秘密の情報・メールアドレス・IP アドレスのマスクと512文字の制限を確かめました。

# おわりに

第54部で、LLM の出力と承認の判断を、AI Defense Manager の側で守るようにしました。

| 項目 | 結果 |
|---|---|
| LLM の `summary`・`reasoning` | 伏せ字にし、2,000文字・4,000文字に制限 |
| 承認 | `no_action` のほかは、サーバーの側で必ず承認が要る（DB に保存するときにも再度あてる） |
| 一時的な遮断 | 公開の IP・証拠2件・承認が要る。プライベートの IP は拒む |
| Wazuh のイベントの取得の API | `event_summary`・`rule_description` も伏せ字にする |
| 試験 | 10件・5件・9件すべて合格 |
| 権限 | `wazuh_relay.py` は `root:ai-defense`・`640` |
| サービス | 再起動し、`/health` は `HTTP 200` |

> **注意：** ソースのファイルを書き換えたあとは、所有者・グループ・モードが `root:ai-defense`・`640` になっているかを確かめてから再起動します。`root:root` だとサービスが読めません。

# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」中編の第29部です。第28部で、Collector は「前に読んでいたファイル（inode 5409383）が見つからない」ため、安全のために起動を止めていることがわかりました。ここでは次のことを行います。

1. 前のファイルがどうなったかを、ログのファイル・圧縮ファイル・チェックサムで確かめる
2. 保存した読み取り位置が、前のファイルの**最後**だったことを確かめる
3. PostgreSQL の重複を防ぐ仕組みを確かめたうえで、読み取り位置を「今の `alerts.json` の先頭」に書き換える
4. Collector を動かし、PostgreSQL に取り込まれたことを確かめる

読み取り位置を勝手に今のファイルの最後に進めると、読み残しが出ます。根拠を1つずつ確かめてから進めます。

## 本書の表記

- コマンドやプログラムは、構築時に実際に使用したものをそのまま掲載しています。改変していません。
- 実行先は、各手順の「実行先」に示します。
  - **VM 220**：security-core（root）
  - **postgresql**：LXC 109（192.168.0.151）。OS のユーザー `postgres`
- アラートの本文は表示しません。PostgreSQL のパスワードは `.pgpass` から読み、表示しません。
- inode・大きさ・時刻・件数は構築時のものです。自分の環境の値に置き換えてください。

⟦C13⟧

⟦C14⟧

⟦C15⟧

⟦C16⟧

1. 1件ずつ別のトランザクションで INSERT する
2. `event_id` の重複（SQLSTATE `23505`）なら取り消して次へ進む
3. INSERT の成功・重複のどちらでも、そのあとで読み取り位置を保存する

5. ファイルが切り替わったら、新しい inode と offset 0 を先に保存してから切り替える

# おわりに

第29部で、Collector を読み残しなしに動かし直しました。

| 項目 | 結果 |
|---|---|
| 前のファイル | 20日の分の圧縮ファイル。大きさ・行・チェックサムで確認 |
| 読み取り位置 | inode 5409517・offset 0 に書き換え（バックアップは `state.json.pre-recovery-20261121`） |
| PostgreSQL | 1,318件を登録、重複 0 |
| 読み残し | 0 バイト |

ローテーションの前後でイベントが欠けていないことまでは証明していません。また、試験用の隠しディレクトリは残ったままなので、次にファイルが切り替わったとき、同じ理由で止まるおそれがあります。次の部で、これを防ぎます。

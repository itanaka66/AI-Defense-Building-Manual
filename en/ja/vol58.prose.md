# はじめに

## 本書について

本書は「AI自律型サイバー防御システム 構築マニュアル」第4巻の第58部です。第57部で、API のトークンによる認証を作り、独立した環境で試しました。本番に入れる前に、トークンの処理と CLI を細かく点検し、見つかった弱いところを直します。

| 見つかったこと | 直し方 |
|---|---|
| トークンのファイルの親のディレクトリがシンボリックリンクだと、その先にファイルを作り、権限も変えてしまう | ディレクトリを `O_DIRECTORY` と `O_NOFOLLOW` を付けて順に開き、`dir_fd` を通してファイルを作る |
| ファイルに改行ではなく文字の `\n` を書いていた | 本当の改行を書く |
| DB の `scopes` に文字列でない要素があると `TypeError` になる | 要素が文字列かを先に確かめる |
| 有効期限に `True` を渡すと1日として通る | `bool` を拒む |
| `scopes` が正しくない JSON だと一覧が止まる | 一覧を止めずに扱う |
| 書き込みの途中で失敗すると、途中のトークンのファイルが残る | 失敗したら、そのファイルだけを消す |

すべて一時の DB・一時のファイルで試し、本番の DB やトークンには触れません。サービスも再起動しません。

# 第4章　有効期限・一覧・書き込みの失敗

## 4.2　有効期限と一覧を直す

> **実行先：VM 230**

|---|---|

| 一覧に秘密の情報が出ない | 合格 |

10件すべて合格でした。

## 4.3　書き込みに失敗したとき

> **実行先：VM 230**

⟦C13⟧

発行の途中でファイルの書き込みに失敗すると、発行したトークンは失効させ、CLI はエラーで終わりますが、途中のファイルが残る場合がありました。

> **実行先：VM 230**

⟦C14⟧

`_write_token_file()` には、ファイルを作ったあとに `write()`・`flush()`・`fsync()` が失敗したときに、ファイルを消す処理がありませんでした。

## 4.4　失敗したら途中のファイルを消す

ファイルを新しく作ったあとで例外が起きたら、同じディレクトリの FD を使って、そのファイルだけを消します。既存のファイルやシンボリックリンクは消しません。

> **実行先：VM 230**

⟦C15⟧

実際に `fsync()` の失敗を起こして試し、途中のファイルが消えること、正しいときは中身と `0600` で保存されることを確かめました（6件すべて合格）。
